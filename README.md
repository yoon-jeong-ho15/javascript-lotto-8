# 기능 목록

## 1. 금액 입력

- [x] 안내 문구 출력 `"구입금액을 입력해 주세요."`
- [x] 입력된 문자열의 공백 제거
- [x] 쉼표가 있는 경우는 쉼표 제거 `15,000 -> 15000`
- [x] '원' 문자가 입력되었다면 제거 `15,000원 -> 15,000`
- [x] 한글로 입력한 경우 숫자로 변환 `삼만원 -> 30000`
- [ ] 예외 상황에는 다시 금액 입력 단계 이동

### 예외 상황

- [ ] 1000 단위로 떨어지지 않는 경우
- [ ] 유효하지 않은 문자를 입력하는 경우
- [ ] 구매 한도(십만원)을 초과하는 경우

## 2. 복권 출력

- [ ] 안내 문구 출력 `"-개를 구매했습니다."`
- [ ] 입력한 금액에서 1,000원당 복권 1 장 출력
- [ ] 각 복권에는 1~45중 중복되지 않는 랜덤한 숫자 6개 출력
  - [ ] 오름차순 정렬

## 3. 당첨 번호 입력

- [ ] 안내 문구 출력 `"당첨 번호를 입력해 주세요."`
- [ ] 1~45중 중복되지 않는 숫자 6개를 하나의 문자열로 입력
- [ ] 공백 제거
- [ ] 쉼표로 숫자를 구분
- [ ] 예외 상황에는 다시 당첨 번호 입력 단계로 이동

### 예외 상황

- [ ] 번호가 정확히 6개가 아닌 경우
- [ ] 숫자 외의 문자를 입력하는 경우
- [ ] 1~45 사이의 숫자가 아닌 경우

## 4. 보너스 번호 입력

- [ ] 안내 문구 출력 `"보너스 번호를 입력해 주세요."`
- [ ] 1~45 까지의 숫자중 당첨번호와 중복되지 않는 숫자 1개를 입력
- [ ] 예외 상황에는 다시 보너스 번호 입력 단계로 이동

### 예외 상황

- [ ] 1~45 사이의 숫자가 아닌 경우
- [ ] 당첨 번호와 중복되는 경우
- [ ] 숫자 외의 문자를 입력하는 경우

## 5. 당첨 확인

- [ ] 복권마다 숫자 일치 갯수 확인
- [ ] 5개 일치하는 경우 보너스 번호 일치 여부 확인
- [ ] 당첨 내역 출력
- [ ] 당첨금과 투자금을 비교해 수익률을 계산 및 출력

# 결정 사항

<details>

## 구매 한도

현실에서도 복권을 구매할 때 한번에 10만원 이상 구매할 수 없게 제한하고 있다. 사용자 경험 측면에서 더 완성도 높은 구현을 위해 해당 과제에서도 구매 한도를 제한했다.

## 금액(만)을 한글로 입력하는 경우

이 부분도 사용자 경험 측면에서 고려해 결정한 사항이다.

한국을 포함한 많은 국가에서 지폐에 숫자와 함께 문자로 금액을 표기하고 있기도 하고, 실제로 적지 않은 사람들이 "삼만원" 혹은 "3만원" 과 같이 문자로 금액을 표현한다.
그래서 당첨 번호와 보너스 번호와 달리 금액에서 만큼은 한글 입력도 허용하기로 했다.

애초에 '예외 처리'의 목적은 무엇일까?

1. 프로그램이 정상적으로 작동할 수 없는 입력이 주어졌을 때.

   - 가령 프로그램은 당첨 번호를 필요로 하는데 사용자가 `사과`를 입력한다면, 프로그램이 계속 정상 작동을 하기 위해서는 새로운 입력을 필요로 하고 사용자에게 요구해야 한다.

2. 프로그램이 사용자의 의도를 정확히 알 수 없을 때.

   - 사용자가 구매 한도 이상의 금액인 `110000`을 입력한다면? 자동으로 구매 한도에 맞춰 복권 100장을 구매하는것으로 처리해야할까? 아니면 `0`을 오타로 간주하고 11장을 구매하는것으로 해야할까? 모호하기 때문에 프로그램은 사용자에게 명확한 의도를 물어봐야 한다.

하지만 사용자가 명확하게 "삼만원" 이라고 입력했다면 위의 두 경우에 해당하지 않는다. 사용자가 정상적인 입력을 명확한 의도를 가지고 입력했다면 그것을 올바르게 해석하는것은 프로그램의 의무라고 생각해서 예외 처리를 하지 않고 변환하는 로직을 추가하기로 결정했다.

## 예외 상황 발생시 해당 단계에 머무르기

이전 과제들에서 잘못된 입력값이 들어오면 프로그램이 종료되었지만, 이번 과제에서는 올바른 입력이 들어올 때 까지 반복해서 입력값을 받아야 한다.

# 문제 상황들

## VSCode `test` 자동 완성 관련

`test`를 사용하려고 `test(`까지 입력을 하면 자동으로 `TextDecoderStream()`이 작성된다.

해결법을 검색해서 [찾아보니](https://github.com/microsoft/vscode/issues/76353) 자동완성을 끄거나 아니면 `acceptSuggestionOnCommitCharacter` 설정을 꺼야 한다고 한다. ';'나 '.'나 '(' 과 같은 commit character를 입력하면 제안을 받아들이는 것으로 간주하는 설정.

그런데 이런 편의기능을 사용하지 않으면서 문제를 해결하고 싶지 않아서 더 [찾아봤다](https://stackoverflow.com/questions/57874114/intellisense-for-jest-not-working-in-vs-code).

간단히 `@types/jest` [패키지를](https://www.npmjs.com/package/@types/jest) 설치하니까 해결되었다.(과제에서는 다른 라이브러리를 허용하지 않으니 이 방법은 적용할 수 없지만.)
